# План следующих шагов

Статус на 25.11.2026: CI на `main` зелёный (запуск #9, коммит 3af33c6). Ранние запуски #3 и #4 были красными или с предупреждениями; их причины не разбирались подробно. Проверить в истории Actions, если нужно.

Ограничение: эти шаги требуют запуска npm и Docker, поэтому выполняются через Claude Code или локально. Каждый шаг — отдельная ветка и PR.

## Шаг 1. Lockfile и воспроизводимая установка
Ветка `chore/lockfile`.
1. `npm install` в корне; проверить, что создан `package-lock.json`.
2. В `.github/workflows/ci.yml` заменить `npm install` на `npm ci`.
3. Удалить шаг экспорта сгенерированного lockfile как artifact (больше не нужен).
4. PR. Ожидаемый результат: CI зелёный, установка через `npm ci`.

## Шаг 2. Аудит зависимостей
Ветка `chore/deps-audit`. Не запускать `npm audit fix --force`.
1. `npm audit --json` и разбор по пакетам: прямые и транзитивные.
2. Для каждой high и moderate уязвимости: есть ли исправление без major-обновления.
3. Отдельный список «принято с обоснованием» в `docs/SECURITY.md`.
4. Предупреждения `node-abort-controller` и `glob@10.4.5`: найти, кто их тянет.

## Шаг 3. Локальная PostgreSQL и миграции
Ветка `chore/local-db`.
1. Добавить `docker-compose.yml` (готово в этом пакете).
2. Проверить: `docker compose up -d db`, затем `npm run prisma:validate` и миграция `prisma migrate dev --name init` в `apps/api`.
3. Закоммитить папку миграций и описать в README процесс миграций.

## Шаг 4. Модель каталога
Ветка `docs/catalog-model`. Документ `docs/CATALOG_MODEL.md` уже в `main`.
1. Директор отвечает на открытые вопросы в документе.
2. После ответов обновить документ и Prisma-схему в отдельном PR.

## Шаг 5. Каталог API и UI
Начинать только после шага 4. Ветка `feat/catalog-api`, затем `feat/catalog-ui`.
